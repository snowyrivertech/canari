The philosophy

Recording froze music
in amber. Canari thaws it.

Before recording technology, every performance was unique — shaped by the room, the weather, the mood of the players, the energy of the people listening.

"Musicians are canaries in a coal mine — their job is to feel things before the rest of us."

Recording was a miracle. It let us preserve music, carry it across time. But preservation required freezing. The vinyl, the CD, the stream — every format is a container, and containers hold things still.

Every format from sheet music to TikTok is just a medium trying to convey something about the human experience. Canari is the next one — and the first that can actually move with it.

What uploading looks like

You bring stems. You set the moments your music belongs in. Canari handles the blends, the listeners, the data — and shows you how your song lives in the world.

01

Drop in your stems

Strings, vocals, drums, pads — whatever you've got. Tag them once. We auto-detect type when we can.

02

Pick the moments

Rainy commute. Sunday morning. Late night alone. Either use ours, or write your own trigger sets — weather, time, location, custom tags.

03

Set the balance per moment

For each trigger × stem: Off Present Featured. That's the whole craft. We do the smoothing.

04

Publish, then watch it live

See which versions get played, in what weather, at what times. Adjust. Republish. The song keeps learning.

Technical architecture

Built on a graph.
Powered by context.

The architecture is built around a proprietary context graph — designed from the start to be the kind of data asset a major platform would want to own. Here's how it's built.

System architecture

Four layers, each feeding the next. The context engine is where the magic lives — everything else enables or delivers it.

🎵
Creation Layer
Artist Upload
Stems, intent, metadata ingested. AI generates contextual variations via MusicGen. Community validates context fit.
🕸
Graph Layer
Neo4j
Songs → stems → moods → contexts → environment. Every listen enriches the graph. The proprietary moat grows with every user.
⚡
Context Engine
FastAPI / Python
Ingests real-time signals. Traverses the graph. Scores and ranks stem combinations. Returns the blend for this exact moment.
🎧
Listener Layer
React
The player. Context display. Social sharing of specific versions. Feedback loop back into the graph.

The context graph

Neo4j sits at the center of everything. The graph captures not just what music sounds like, but what it means — and in which contexts it belongs. This is the asset that compounds over time.

// Core graph schema — Canari context model

(Song) -[:HAS_STEM]-> (Stem)
(Stem) -[:EVOKES]-> (Mood)
(Mood) -[:FITS]-> (Context)
(Context) -[:TRIGGERED_BY]-> (EnvironmentalFactor)
(EnvironmentalFactor) -[:INCLUDES]-> (Weather)
(EnvironmentalFactor) -[:INCLUDES]-> (TimeOfDay)
(EnvironmentalFactor) -[:INCLUDES]-> (Location)
(Listener) -[:IN]-> (Context)
(Listener) -[:HEARD]-> (Song)
(Listener) -[:RESPONDED_TO]-> (Version)

// Graph traversal: given Context → find best Stem blend
MATCH (c:Context)-[:TRIGGERED_BY]->(e:EnvironmentalFactor)
MATCH (s:Stem)-[:EVOKES]->(m:Mood)-[:FITS]->(c)
RETURN s, score(s, c) ORDER BY score DESC

Core stack

Chosen for speed to demo, Python-native tooling, and graph-first data modeling. Everything runs local first, cloud-ready.

Backend

FastAPI + Python

Python-native, async-ready, fast to iterate. The context engine, signal ingestion, and stem mixing logic all live here. Ideal for a data scientist building solo.

  • Signal ingestion from weather + location APIs
  • Graph query construction and scoring
  • Stem blend computation and serving
  • Artist upload and variation generation endpoints
Graph Database

Neo4j

The proprietary moat. Cypher queries make context traversal natural — finding which stems fit a moment is a graph problem, not a table problem. Richer and more explainable than any vector DB.

  • Context-to-stem relationship modeling
  • Listener behavior accumulation
  • Cold start resolution via graph inheritance
  • Explainable: why this version, for this moment

AI layer

AI closes the content gap — artists upload stems and intent, AI handles variation generation. No artist has to compose every version manually.

Generation

MusicGen (Meta)

Open-source model for generating stem variations conditioned on text and audio. Artists set the soul, AI extends it contextually.

Stem Separation

Demucs

For catalog tracks without stems, Demucs separates existing recordings into component stems. Unlocks legacy catalog without re-recording.

Context Signals

OpenWeatherMap + IP Geo

Real-time weather, location, time, and season. Free tier sufficient for demo. Expands to biometric and social signals in v2.

Frontend approach

React built with AI assistance — not the core competency, but not a blocker. The goal is a demo that makes someone feel the product, not a polished app.

Player UI

React + AI-assisted dev

The listening experience, context display, and moment-switching interface. Built fast with AI tooling, iterated based on what makes the demo land.

Artist Upload

Minimal creation interface

Stem upload, intent tagging, graph authoring — just enough for an artist to put music into Canari and see how it lives. Not a DAW. Not competing with creative tools.
